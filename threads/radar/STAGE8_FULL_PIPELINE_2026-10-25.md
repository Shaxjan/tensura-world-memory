Статус: **автоматическое обновление чернового индекса включено, но первый новый реальный пост после подключения ещё не поступил**. Редакторские утверждения и публикации строго вне автоматизации.

## 1. Ежедневный вход

Активная задача ChatGPT «Радар Threads: безопасная синхронизация» запускается ежедневно в **08:00 Asia/Krasnoyarsk** и, если подключённый Windsor.ai возвращает свежие, корректные, непротиворечивые данные, сохраняет только новый неизменяемый JSON в `threads/radar/inbox/` Draft-ветки. Последнее подтверждённое выполнение на момент настройки: 25 октября 2026.

Объём данных не равен полному экспортy аккаунта; Windsor.ai и тариф Trial могут ограничивать доступность и полноту. Публикации 21:00 и авторские продолжения нельзя выводить из неполной выборки как гарантированно восстановленные.

## 2. Автоматическая цепочка GitHub

[radar-stage8-auto-index.yml](../../.github/workflows/radar-stage8-auto-index.yml): триггер на **новый файл `threads/radar/inbox/windsor-*-retrieved.json`** или ручной запуск. Исполнение ограничено веткой `radar-stage-b-index-20261020` и исходным репозиторием.

1. Повторная нативная приёмка текущего архива, включая все Python/Node тесты.
2. [stage8_upgrade.py](./stage8_upgrade.py) запускает [stage8_preview.py](./stage8_preview.py): в изолированной временной папке сверяет все исходные ID, неизменность ранее индексированных записей, подлинный провайдерский формат, SHA-256, пары сохранённых `inbox` и `snapshots`; делает **две одинаковые пересборки**. При конфликте процесс прекращается.
3. Только при появлении новых валидных корневых ID готовит снимки и индекс в одноразовой копии; исключает репосты из авторских корней. Статусы и планируемые редакторские публикации остаются отдельными.
4. [stage8_rescreen.js](./stage8_rescreen.js) вычисляет обновлённые `reserve/automated-current-ideas.json` и `reserve/automated-current-screening.json`, всегда для **30 идей без автоматического утверждения**. Снимок более чем суточной давности помечается устаревшим.
5. Повторная полная нативная приёмка уже обновлённого индекса; отдельная проверка отчёта 30 идей.
6. [stage8_commit_guard.py](./stage8_commit_guard.py) разрешает к коммиту только валидированные `snapshots/windsor-promoted-...`, три индексных файла и два файла резерва. Неожиданные пути, неучтённые ID, ошибки и конфликтующие данные блокируют запись.
7. Один Git-коммит с откатом при неуспехе шага до `git push` (на одноразовом runner; никакие файлы не попадают в GitHub до push). `git push` строго в черновую ветку; конкурентное изменение удалённой ветки отклоняет не-fast-forward отправку. Слияние с `main` не выполняется.

При отсутствии новых корней: `NO_NEW_ROOTS`, без Git-коммита. При ошибке любого шага: остановка, без новых коммитов или заявлений о полной проверке.

## 4. Границы автономности

**Техническая обработка нового пригодного входящего снимка автоматизирована.** Но ни тест, ни код не доказывают, что Windsor.ai гарантированно доставит каждую новую публикацию; это требуется проверять по реальным ежедневным запускам. Уведомления ChatGPT-задачи зависят от пользовательских настроек, а GitHub Actions сообщает о сбоях только через доступные механизмы GitHub.

Автоматическая оценка сюжета — предварительная: смысловая новизна, точность книжного канона, утверждение текста и фактическая публикация остаются за редактором. Любые статусы `PRECHECKED_LOW_SIMILARITY` и `REVIEW_REQUIRED` нельзя трактовать как утверждение.

Следующий контроль: после **первого нового реального входящего снимка** проверить, что этот GitHub workflow завершился `Success`, индекс вырос ровно на число новых авторских ID, резерв повторно пересчитался, а оригинальные снимки и старые тексты остались неизменны.
