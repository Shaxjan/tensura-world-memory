**Статус:** изолированная разработка в ветке `radar-stage-b-index-20261020`. Ничего не публикует и не планирует в Threads. Не обращается к репозиторию игры.

## Фактический срез (20.10.2026)

- Исторический полный архив: 414 авторских корневых постов, 883 пронумерованные части (срез до 12.10).
- Дополнительные снимки Windsor.ai за 13–21.10: 37 записей, в том числе 33 новые авторские корневые публикации и 4 репоста.
- Рабочий индекс: **447** уникальных опубликованных авторских постов.
- Отдельный редакционный индекс: **40** записей `posts.json`: 32 имеют исторический статус `published`, 8 — `scheduled`; **23** карточки ещё не сопоставлены с публикациями по прямым URL.
- Срез статусов редакционного журнала НЕ означает подтверждения фактической публикации запланированных материалов.
- Для 33 новых корневых публикаций авторские ответы / продолжения ещё не восстановлены: `chain_complete=false`.

## Состав

- `snapshots/windsor-2026-10-13_to_2026-10-20.json` и `snapshots/windsor-2026-10-21.json`: сохранённые read-only результаты Windsor.ai; без паролей и токенов
- `index/posts.jsonl`: индекс публикаций по `post_id`; оригинал и очищенная поисковая версия разделены
- `index/editorial.jsonl`: независимые редакционные записи и статусы
- `index/manifest.json`: числовые проверки, происхождение данных и ограничения
- `radar.py`: перестроение, аудит и полнотекстовый поиск средствами стандартной библиотеки Python 3.10+ и SQLite FTS5
- `test_radar.py`: тестовый набор на искусственных данных

## Запуск локально из корня клонированного репозитория

```bash
python threads/radar/radar.py verify
python threads/radar/radar.py search "Молли Уизли часы"
python threads/radar/radar.py search "Хагрид фотоальбом"
python threads/radar/radar.py search "Локонс" --limit 15
python threads/radar/test_radar.py
```

Воспроизводимая сборка индекса из **неизменяемых** исходных архивов и зафиксированного снимка:

```bash
python threads/radar/radar.py build
python threads/radar/radar.py verify
```

Для другого корневого каталога используйте `--repo-root /path/to/repository` перед подкомандой. Пересборка перезаписывает только производные файлы `threads/radar/index/*`, не изменяет `posts.json`, `full-posts-verified.json`, месячные архивы, аккаунты или production.

## Поиск и ограничения

Поиск возвращает **кандидатов на проверку**, с датами, ссылками, короткими фрагментами и метками статуса. Включает и запланированные записи из редакционного журнала, чтобы не предложить будущую публикацию повторно.

Поиск использует токены и префиксы, а не обученную семантическую модель. Число `coverage` — доля совпавших поисковых слов, а **не процент оригинальности, смысловой близости или уверенность**. Лексический поиск через `radar.py search` не присваивает классы смысла. Для предварительной проверки по пяти категориям используйте отдельный `semantic_cli.js` из раздела «Этап В» ниже; окончательный вывод требует оценки редактора.

Редакционные карточки без прямой подтверждённой ссылки остаются самостоятельными. Запрещено объявлять старую карточку опубликованной по совпадению темы или по дате в календаре.

**Свежесть:** новый Windsor-снимок сделан 20.10.2026. Импорт новых публикаций после этой даты пока ручной; автоматическая синхронизация и полное восстановление авторских ответов — отдельный этап Д. Кэш Windsor.ai может содержать не самые свежие просмотры.

**Возможность FTS5:** если локальный Python собран без расширения SQLite FTS5, используется более простой префиксный поиск.

## Приёмка

Индекс не считается смысловым антиповтором до тестов этапа В. Для каждого нового сюжета редактор должен оценивать событие, конфликт, ракурс, эмоциональный вывод и подтверждение канона. Особенно важны контрольные эпизоды с часами Фабиана и фотоальбомом Хагрида.

В этом чате проведены проверки целостности сохранённых JSON-источников и исходной ветки. Выполнение Python-тестов в реальной рабочей среде следует подтверждать отдельно — наличие тестового файла не является доказательством его успешного выполнения.


## Этап В — предварительная проверка сходных сюжетов (21.10.2026)

**Файлы:** `semantic.js` (библиотека Node.js без сторонних пакетов), `semantic_cli.js` (команда чтения), `semantic.test.js` (14 регрессионных сценариев).

Метод: сравнение слов и нормализованного русского текста, предварительная разметка нескольких известных сюжетных событий, выделенные драматургические поля идеи: `event`, `characters`, `viewpoint`, `conflict`, `conclusion`. Список событий намеренно ограничен и не заменяет разметку всех 447 публикаций.

Для проверки идеи создайте локальный `idea.json` (самостоятельный файл, не публикуйте его):

```json
{
  "text": "Краткая завязка сюжета без готового поста",
  "event": "Конкретное событие",
  "characters": ["Персонаж A", "Персонаж Б"],
  "viewpoint": "Чья перспектива",
  "conflict": "Драматургическое противоречие",
  "conclusion": "Чем идея отличается по смыслу"
}
```

Из корня клона редакционного репозитория:

```bash
node threads/radar/semantic_cli.js idea.json --as-of 2026-10-21
node --test threads/radar/semantic.test.js
```

Команда читает `index/posts.jsonl`, `index/editorial.jsonl`, `index/manifest.json`. Без `--last-synced` ориентируется на дату в манифесте, по умолчанию отказывает в статусе новой истории при устаревании на один день или более. Для будущей актуальной работы необходимо сначала загрузить реальные свежие записи и перестроить индекс.

Статусы: `DUPLICATE` — почти точное совпадение; `SAME_STORY` — повтор известного события без доказанного нового взгляда; `NEW_ANGLE` — совпадающее событие и явно отличающаяся перспектива с конфликтом; `NEW_STORY` — предварительно отдельная история при достаточных полях и свежем снимке; `REVIEW_REQUIRED` — неоднозначность, свежесть отсутствует или может совпадать утверждённый/запланированный материал.

Все категории, кроме почти дословного совпадения, требуют редакторской верификации. Высокая лексическая близость не равна одинаковому художественному конфликту. Точное число найденных совпадений не является оценкой процента оригинальности.

### Что проверено, а что пока нет

- Фактические JSONL и классификатор: **14/14 регрессионных сценариев PASS** в JS-исполнителе с подачей настоящих индексных данных; см. `index/validation-stage-c-2026-10-21.json`.
- Отдельный вызов `node --test` и Python `test_radar.py` из клона репозитория **ещё не подтверждён**, поэтому эти командные проверки остаются обязательным пунктом технической приёмки.
- Отдельно проверены контрольные сюжеты Молли и часов Фабиана, Хагрида и альбома, изменение точки зрения, репосты, отменённый черновик и конкурирующая запланированная публикация.
- Полная сюжетная разметка всех 447 постов, количественная оценка ложных блокировок на большой размеченной выборке и автоматическая синхронизация — **не завершены**.

Для воспроизводимой пересборки Python читает все сохранённые файлы `snapshots/windsor-*.json` в порядке имён; новые записи добавляются по уникальному `post_id`. Последующий снимок с тем же ID обновляет его. Эта функция ещё требует самостоятельного запуска при приёмке.

Изменения находятся только в Draft PR. Никаких публикаций в Threads и изменений основного `main` или игрового репозитория.
