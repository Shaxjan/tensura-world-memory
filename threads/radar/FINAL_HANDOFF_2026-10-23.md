## Как предлагать темы редактору

1. Проверить дату последнего снимка. **Любая публикация или новый день после 23 октября требует повторной синхронизации и рескрининга**; старый вывод автоматически не становится подтверждением уникальности.
2. Искать и сравнивать не названия, а сцену, персонажей, предметы, точку зрения, конфликт, главную мысль и эмоциональный вывод. Учитывать `search_text` вероятных продолжений и самостоятельный редакционный журнал.
3. Просматривать исходные посты по ссылкам из `similar_refs`. Пометка `PRECHECKED_LOW_SIMILARITY` не равна `UNIQUE` и не отменяет редактора. `REVIEW_REQUIRED` не может быть повышена автоматически.
4. Проверить канон по книжному первоисточнику; для Поттерианы использовать имена перевода Росмэн. Любые придуманные мысли и диалоги обозначать как авторскую интерпретацию.
5. Предлагать три **темы**, аргументировать фаворита. **Пост пишется только после выбора автора**; `scheduled` не равно `published`.
6. После принятия текста фиксировать решение в редакционном журнале отдельно от фактической публикации; никаких автоматических публикаций.

**Известные антиповторы:** часы Фабиана, фотоальбом Хагрида, зеркало Сириуса, прежняя G21 «Автор заклинания лечит его жертву» (близкий пост о ранении Драко). Пара постов о зачарованных галлеонах Гермионы содержит общую завязку; не создавать новую вариацию того же вывода.

## Безопасное обновление: только отдельная `radar-*` ветка

Получить только **законную, адресную, read-only** выгрузку @mirpottera через доступный подключённый источник. Проверить полноту и дату среза и сохранить исходный JSON без изменения текста.

```bash
# 1. Просмотр изменений, ничего не записывает
node threads/radar/snapshot_intake.js /path/to/export.json

# 2. Только после просмотра коллизий и в отдельной ветке
node threads/radar/snapshot_intake.js /path/to/export.json --write-local --date YYYY-MM-DD

# 3. Производный индекс (только radar-ветка; предварительно сохранить diff)
python threads/radar/radar.py build
python threads/radar/radar.py verify

# 4. Нативная приёмка на клоне с полной историей
python -m unittest discover -s threads/radar -p 'test_*.py'
node --test threads/radar/semantic.test.js threads/radar/reserve.test.js threads/radar/snapshot_intake.test.js threads/radar/reserve-current.test.js

# 5. Проверка активного резерва на фактическую дату последнего снимка
node threads/radar/reserve_check.js YYYY-MM-DD
```

**Нельзя** просто увеличить `source_index_date`: при новом снимке сначала пересмотреть все 30 карточек и заново сохранить связи с соседними публикациями. Старые версии R1–R3 сохранять для истории, но не выдавать за актуальный резерв.

После сборки проверить `git status`, `git diff` и изменения всех файлов; допускаются только ожидаемые правки под `threads/radar/`. Если текст известного `post_id`, ссылка или дата изменились — **остановить импорт**, расследовать источник. Метрики просмотров могут обновляться из более нового снимка без изменения текста. Для авторских продолжений обязательны ссылка на собственный корневой пост и интервал 0–90 секунд; это лишь вероятная классификация.
