## Как проверять дальше

В корне клонированного репозитория с Node.js:

\`\`\`bash
node threads/radar/reserve_check.js 2026-10-21 > radar-check.json
node --test threads/radar/reserve.test.js
\`\`\`

Команда **ничего не публикует**, выводит JSON со ссылками на близкие посты. При дате после 21.10.2026 результаты 30 идей переходят в \`STALE_RECHECK\`, пока реальные новые публикации не синхронизированы. После этапа Д сначала обновить индекс и его \`source_index_date\`, затем перезапустить проверку.

## Критерии допуска из резерва в основной редакционный чат

1. Проверить свежесть индекса и реальную опубликованную ленту, включая недавние авторские продолжения.
2. Просмотреть ссылки на ближайшие сюжеты по смыслу, особенно \`REVIEW_REQUIRED\`.
3. Сверить книжную сцену, имена и обстоятельства с первоисточником (для Поттерианы — русский перевод Росмэн); художественные монологи пометить как вымысел.
4. Отобрать три идеи с разной драматургией и выбрать своего фаворита. **Не писать целый пост до выбора автора.**
5. Нельзя повышать статус до \`approved\`, \`scheduled\` или \`published\` автоматически.

**Ограничение приёмки:** тесты 11/11 выполнены в изолированном JS-исполнителе с адаптированными \`node:test\`, \`assert\` и \`fs\`. Прямой запуск \`node --test\` и Python на рабочем компьютере ещё не подтверждён. Полный первоисточник всех идей также ещё не сверен.
