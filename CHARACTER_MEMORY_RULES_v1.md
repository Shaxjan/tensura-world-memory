# CHARACTER_MEMORY_RULES_v1

This file is the compact operating guide for NPC characterization. Full character data lives in `characters/`.

## One NPC = one character file
Do not scatter a personality across random correction files. Corrections remain historical evidence; the current character file is the readable consolidated profile.

## Characterization grows from scenes
An NPC starts sparse. Every meaningful appearance can add grounded details. Repeated participation makes the profile progressively richer. The goal is continuity, not instant encyclopedic biographies.

## What can be added
- observed actions and reactions;
- direct statements;
- stable preferences demonstrated more than once;
- goals and decisions the player has causally learned;
- relationship changes that actually happened;
- memories created by direct shared encounters;
- established source/canon traits when this character is explicitly that canon character.

## What must not be invented
- secret thoughts;
- private plans as player knowledge;
- emotions with no evidence;
- childhood/history not established;
- romance/jealousy just because a scene is romantic;
- movement or actions merely to keep the scene entertaining;
- dialogue for NPCs who have no reason to speak.

## Depth update pattern
When an NPC becomes recurring, update the same file. Prefer incremental additions with evidence and timestamps. If a later event changes a trait, preserve the old trait as historical and record the new trait as the current state rather than merging contradictions.

## NPC autonomy
Characters are active agents. Their own obligations, routines, relationships and goals continue when Arlequino is silent. Autonomy must remain causally bounded: an NPC does only what their current knowledge, capabilities, personality and commitments make plausible.

## Knowledge boundary
The character may know something without Arlequino knowing it. The narrator must not leak hidden character knowledge, private plans or off-screen actions unless a causal observation/report later reveals them.

## Scene realism
Do not force every NPC into every scene. Do not make the whole group react in chorus. Silence, delay, disagreement, mundane business and separate conversations are valid outcomes.

## Priority
1. Current explicit user correction/retcon.
2. Later authoritative event/state.
3. Existing character file's current state.
4. Earlier history/canon.
5. Never guess when the evidence is insufficient: use `UNKNOWN` or `not_yet_authored`.
