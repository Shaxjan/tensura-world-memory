# Tensura World Memory — Master Save Protocol

Этот файл задаёт обязательный порядок работы мастера с `world_save.json`.

## Источник истины

`world_save.json` — единственный актуальный источник состояния симуляции между чатами.

При конфликте между памятью чата и SAVE приоритет имеет SAVE, кроме случаев, когда пользователь прямо исправляет данные.

## Перед продолжением сцены

1. Прочитать `world_save.json` целиком через подключённый GitHub.
2. Проверить `save_version`.
3. Прочитать как минимум:
   - `current_state`
   - `characters`
   - `timeline`
   - `events`
   - `world`
   - `relationships`
   - `economy`
   - `rules`
   - `integrity_report`
4. Продолжать только с `current_state.last_scene.continue_from`.
5. Значения `UNKNOWN` не заменять догадками.

## После значимой сцены

Обновлять SAVE только после сцены, которая изменила состояние мира, персонажей, денег, отношений, знаний, местоположения, времени или активных событий.

Перед записью:

1. Повторно получить актуальный `world_save.json` и его текущий SHA.
2. Убедиться, что `save_version` совпадает с версией, с которой началась запись. Если файл уже изменился, сначала перечитать его и объединить изменения, а не перезаписывать вслепую.
3. Внести только фактически подтверждённые изменения.
4. Увеличить `save_version` ровно на 1.
5. Сохранить полное содержимое обратно в `world_save.json` через GitHub.
6. Commit message: `SAVE vN — <короткое описание сцены>`.

## Что обновлять

### `current_state`

Обязательно обновлять:
- world time;
- location Маэстро;
- состояние Маэстро;
- personal cash;
- `last_scene.summary`;
- `last_scene.continue_from`;
- active storylines;
- pending consequences.

### `timeline`

Каждая значимая сцена получает новую запись с уникальным ID.

Хранить:
- время;
- место;
- участников;
- факты сцены;
- последствия.

Не переписывать старые записи ради красоты формулировки, если факты не менялись.

### `characters`

Для затронутых персонажей обновлять:
- location;
- status;
- goals, если они реально изменились;
- knows / does_not_know;
- last_confirmed_appearance;
- важные notes.

NPC не получают знания без реалистичного источника.

### `events`

События разделять на:
- `active`;
- `scheduled`;
- `completed`.

Автономные события мира продолжаются независимо от Маэстро, если ничто им не мешает.

### `relationships`

Менять отношения только при наличии причины в сцене.

Не считать отношение A→B автоматически равным B→A.

### `economy`

Критически важно:
- личная касса Маэстро хранится отдельно от промо- и проектных бюджетов;
- после публичного выступления фиксировать доход, расход, чистый результат и новый баланс;
- не восстанавливать деньги приблизительно;
- итоговая касса должна сходиться с журналом подтверждённых операций.

## Запрещено

- придумывать недостающие факты;
- заменять `UNKNOWN` вероятным вариантом;
- ретконить подтверждённую историю без прямого исправления пользователя;
- выбирать реплики, чувства, решения или значимые действия за Маэстро Арлекино;
- телепортировать NPC или менять их знания без причины;
- смешивать личные деньги Маэстро с отдельными фондами;
- перезаписывать SAVE без проверки актуального SHA.

## Контроль перед commit

Перед каждой записью проверить:

- нет ли противоречия `current_state` и `timeline`;
- совпадает ли касса с экономическим журналом;
- не знает ли NPC невозможного для него факта;
- физически ли возможно текущее местонахождение персонажей;
- корректно ли перенесены события между active / scheduled / completed;
- указан ли точный `continue_from`;
- новая версия SAVE = предыдущая + 1.

## Режим сохранения

GitHub уже хранит историю каждого изменения `world_save.json`, поэтому отдельный полный backup-файл после каждой сцены не нужен. История commit'ов является журналом версий и позволяет откатиться при ошибке.
