# Tensura World Memory — Fast Delta Save Protocol

Цель этого протокола — сохранить долговременную память мира без многоминутного переписывания большого SAVE после каждой сцены.

## 1. Архитектура

### `world_save.json`

Это **базовый снимок мира**.

Текущий базовый снимок: SAVE v3.

Во время обычной игры **НЕ переписывать `world_save.json` после каждой сцены**.

Он содержит широкую историческую и мировую базу до версии базового снимка.

### `live_state.json`

Это **главный оперативный источник текущего состояния**.

Он маленький и должен содержать:
- текущую `save_version`;
- world time;
- Маэстро: location/state/cash;
- `last_scene` и `continue_from`;
- текущий состав путешествия;
- живые статусы важных NPC;
- активные/запланированные события;
- актуальные отношения;
- текущую экономику;
- unresolved/UNKNOWN;
- критические правила.

Во время игры обновляется именно `live_state.json`, а не большой `world_save.json`.

### `journal/save_vNNNN.json`

Каждая значимая сохранённая сцена после базового снимка получает отдельный **маленький append-only delta-файл**.

Пример:

`journal/save_v0004.json`

Он хранит только изменения этой сцены, а не весь мир.

## 2. Источник истины

Приоритет:

1. прямая последняя коррекция пользователя;
2. `live_state.json` — текущее состояние;
3. journal-файлы после базового snapshot — история изменений после базы;
4. `world_save.json` — базовый широкий снимок/история;
5. память отдельного чата.

`UNKNOWN` никогда не заменять догадкой.

## 3. Новый чат / восстановление

При входе в новый чат:

1. Один раз прочитать `MASTER_SAVE_PROTOCOL.md`.
2. Прочитать `live_state.json`.
3. Один раз прочитать `world_save.json`, если нужен полный исторический/мировой фон.
4. Не читать все journal-файлы подряд без необходимости: их итог уже должен быть применён в `live_state.json`.
5. Journal использовать для проверки конкретной прошлой сцены или противоречия.
6. Продолжать только с `live_state.last_scene.continue_from`.

В одном уже идущем чате не перечитывать эти файлы перед каждой репликой.

## 4. Когда сохранять

Не сохранять после каждого взгляда, шага или короткой реплики.

Сохранять только после значимой сцены или естественной границы, если изменились:
- время;
- локация;
- важное решение;
- отношения;
- знания NPC;
- деньги/имущество/контракт;
- состав группы;
- active/scheduled/completed event;
- важный автономный мировой процесс;
- точка продолжения, которую нельзя потерять при переносе в новый чат.

Несколько коротких реплик одной сцены объединять в один checkpoint.

## 5. Быстрое сохранение — нормальный путь

После значимой сцены:

1. Использовать рабочее состояние текущего чата.
2. **Не читать и не переписывать `world_save.json`.**
3. Взять текущую версию из `live_state.json`/контекста.
4. Новая версия = старая + 1.
5. Создать новый маленький файл `journal/save_vNNNN.json`.
6. Обновить только маленький `live_state.json`.
7. Сохранить новый SHA `live_state.json`, возвращённый GitHub, для следующего checkpoint.

Обычное сохранение должно требовать только:
- один `create_file` для journal;
- один `update_file` для `live_state.json`.

## 6. Формат journal delta

Каждый `journal/save_vNNNN.json` должен иметь примерно такую структуру:

```json
{
  "from_version": 3,
  "to_version": 4,
  "world_time": "T+117 ~13:40",
  "scene_id": "scene_...",
  "summary": "Короткое фактическое описание завершённой сцены",
  "changes": {
    "maestro": {},
    "characters": [],
    "relationships": [],
    "events": [],
    "economy": [],
    "world": []
  },
  "continue_from": "Точная точка продолжения",
  "unknowns_preserved": []
}
```

Не копировать туда все неизменившиеся персонажи, всю историю или весь мир.

## 7. SHA и конфликты

При первом чтении `live_state.json` в новом чате запомнить его blob SHA.

После успешного `update_file` использовать возвращённый новый `content_sha` для следующего сохранения.

Поэтому **не делать `fetch_file` перед каждым checkpoint**.

Если GitHub отклоняет update из-за SHA/conflict:

1. прочитать только свежий `live_state.json`;
2. сравнить версии;
3. объединить изменения;
4. повторить запись с новым SHA.

Большой `world_save.json` при таком конфликте читать не нужно, если противоречие не требует исторической проверки.

## 8. Что обязательно держать актуальным в `live_state.json`

После checkpoint проверить только затронутые области:

- `save_version`;
- world time;
- Маэстро location/state/cash;
- `last_scene.summary`;
- `last_scene.continue_from`;
- текущий состав/логистика путешествия;
- статусы и знания реально затронутых NPC;
- active/scheduled events;
- отношения, если сцена их изменила;
- unresolved/UNKNOWN;
- экономика, если были деньги.

## 9. Экономика

Критически важно:

- личная касса Маэстро отдельно от промо- и проектных фондов;
- после публичного выступления фиксировать income / expense / net / new personal cash;
- не восстанавливать деньги приблизительно;
- если сцена денег не меняла, достаточно записать `economy_change: none` в delta.

## 10. Запрещено

- переписывать 100+ KB `world_save.json` после каждой обычной сцены;
- перечитывать весь SAVE перед каждой репликой;
- сохранять каждую микрореплику;
- заменять `UNKNOWN` догадкой;
- ретконить факты без прямой коррекции пользователя;
- выбирать реплики, чувства, решения или значимые действия за Маэстро Арлекино;
- давать NPC знания без реалистичного источника;
- смешивать личные деньги с отдельными фондами;
- перезаписывать конфликт SHA вслепую.

## 11. Периодическая компактизация

Во время обычной игры компактизацию не запускать.

После большой арки, примерно каждые 20–50 SAVE или по прямой просьбе пользователя можно отдельно:

1. собрать `world_save.json` + journal в новый свежий базовый snapshot;
2. обновить base version в `live_state.json`;
3. оставить старые journal-файлы как архив GitHub.

Это обслуживание должно выполняться отдельно от RP-сцены и не замедлять обычную игру.

## 12. Целевое время

Нормальный checkpoint должен быть маленьким: несколько KB вместо полного SAVE.

Цель — десятки секунд, а не минуты. Абсолютное время ответа платформа не гарантирует, но мастер не должен выполнять тяжёлое полное сохранение без причины.
