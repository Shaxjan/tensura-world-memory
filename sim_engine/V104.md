# Simulation Engine v1.0.4 — Character Core

v1.0.4 is the first persistent named-character layer. It does **not** try to simulate every part of a person at once. It establishes the stable state that later autonomy, memory, relationships and needs can safely build on.

## First calibrated character

Borga is the first Character Core because v1.0.3 already has a source-grounded connection between Borga and the three Eurazania training sites, and the current LIVE history contains a causal search lead involving him.

The engine does not invent a personality to fill the new schema. Until authored or causally learned, Borga's personality fields remain explicitly `not_yet_authored`; relationships and memories begin empty.

## Character Core

The persistent core contains:

- stable identity;
- autonomy tier;
- current role goal and obligation;
- personality placeholder without invented traits;
- relationship store;
- memory store;
- causal knowledge policy;
- future needs/resources placeholders;
- reference to the current character plan.

Authority is `NON_CANON_MECHANICAL_PROSPECTIVE`: it governs the simulation from materialization forward and is not a retroactive claim about unseen history.

## Persistent daily role plan

v1.0.3 chose Borga's hidden place independently per hour. v1.0.4 replaces that with one deterministic daily role plan persisted in authoritative state.

The first plan intentionally models only what the engine can currently justify:

- role-duty blocks at one of Borga's three established training sites;
- finite local-travel blocks between duty sites;
- unresolved personal-time blocks;
- unresolved regional activity outside scheduled duty.

During a role-duty block the hidden prospective plan may have an exact training site. During travel/personal/unresolved blocks the exact place is `UNKNOWN`; the engine must not invent route geometry or a convenient destination.

## Migration continuity

Activation starts from a compact snapshot of the confirmed v1.0.3 head.

If a valid v1.0.3 Borga presence fact exists for the current day, v1.0.4 uses its training site as the first duty-block anchor for the materialization day. This prevents the engine upgrade from silently contradicting the causal evidence already produced by the current LIVE search.

Activation itself is an append-only `character_core_activation` runtime event. It consumes zero game minutes, changes no player choice, cash or region, and does not overwrite the last gameplay turn in the session read-model.

## Hidden-state rule

Character Core and daily plans are engine state. They are **not narrator knowledge** and must not be exposed to the player unless there is a causal observation or transmission.

Search continues to use the existing v1.0.3 causal interface:

`hidden character plan -> direct observation/testimony -> player knowledge`

## Scope boundaries

v1.0.4 deliberately does not yet implement:

- autonomous goal selection;
- authored Borga personality;
- relationship score changes;
- long-term episodic memory;
- biological needs;
- private possessions/economy;
- AI/LLM agent calls;
- full travel-path simulation.

Those are later layers. The purpose of v1.0.4 is to make the character persistent before making the character clever.

## Guardrails

- Never choose Arlequino dialogue, feelings, decisions or significant actions.
- Never expose hidden Character Core/plan state as player knowledge.
- Never invent personality, memories, relationships or possessions to fill empty fields.
- `UNKNOWN` stays `UNKNOWN`.
- Existing journal events remain immutable.
- Character activation consumes zero world time and zero money.
- v1.0.3 living scenes and causal testimony remain regression requirements.
