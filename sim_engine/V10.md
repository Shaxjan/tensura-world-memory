# Tensura Simulation Engine v0.10 — Scene Bridge & Executable Autonomy

v0.10 closes the two runtime gates left by v0.9 without switching the live campaign yet.

## Structured ordinary-scene bridge

Normal roleplay no longer needs the narrator to mutate state outside the engine just because an action is not a combat/buy/travel command.

The bridge records the player's raw text verbatim and classifies grounded components such as:

- dialogue / requests;
- singing and instrumental performance;
- local movement or search attempts;
- object hand-off offers;
- physical interaction attempts;
- self-actions;
- generic non-high-risk player actions.

A crucial distinction is `event_only` versus `pending_resolution`.

Speech or a performance can be recorded as the player's action without inventing an external outcome. Local navigation, NPC response/consent, hand-off acceptance and other world-dependent outcomes are stored as pending resolution. The narration contract explicitly forbids the GM from resolving them in prose.

The generic bridge cannot bypass combat, money, magic/treatment or inter-region travel guards. Those remain under their dedicated engine mechanics.

## Current-scene object provenance

If the pointed LIVE delta itself establishes possession of a scene object, v0.10 may seed that claim. For LIVE v159 this includes Rena's guitar in Arlequino's possession with permission. A hand-off action remains an offer until the recipient/world response is resolved; the bridge does not silently change ownership/possession.

## Executable autonomy commitments

Every imported autonomous commitment is assigned a deterministic prospective runtime handler and due time.

Supported families:

- NPC task work;
- festival/tournament project work;
- mail;
- guarded opaque commitments.

Unknown semantics do not become invented outcomes. For example, mail with no authoritative route or dispatch price records causal blocking plus initiative to seek a method/quote; it does not magically arrive and it does not spend money.

The `wait` command is re-enabled because time advancement now runs this commitment scheduler on the same authoritative world clock.

## Shadow-only cutover rehearsal

v0.10 still does not replace `live_state.json` as source of truth. The real-repository rehearsal must:

1. migrate the current LIVE state through v0.9;
2. install the scene/autonomy bridges;
3. export a v0.10 portable checkpoint;
4. restore it into a fresh v0.10 SQLite runtime with an identical canonical hash;
5. submit the current continuation `Иду искать Боргу.`;
6. require a pending local-navigation resolution with no teleport, cash change or time fabrication;
7. advance 15 shadow minutes through the authoritative `wait` command;
8. require at least one autonomous commitment execution while preserving player cash and region;
9. resolve the shadow gate only if all checks pass.

If all runtime gates are resolved, the rehearsal may report `live_cutover_ready=true`. That is readiness, not an automatic live switch. Actual source-of-truth cutover is a separate v1.0 operation.
