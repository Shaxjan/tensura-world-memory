# Tensura Simulation Engine v0.2 — Autonomous World Lab

v0.2 is an isolated simulation laboratory. It does **not** replace the current Arlequino campaign yet.

## Why v0.2 exists

The chat-only prototype exposed five structural failures:

1. text/remote saves were too slow;
2. economy could drift because the LLM was doing arithmetic/state management;
3. crowd/NPC reactions were generic and weakly justified;
4. NPCs mostly waited for the player;
5. world logic was literary rather than causal.

v0.2 moves those responsibilities into deterministic code + SQLite. An LLM should eventually narrate results, not invent state transitions.

## Implemented in v0.2

### Persistent state
- SQLite is authoritative for the lab world.
- No JSON rewrite is required for a normal state change.
- WAL mode enabled.
- Economy, inventory, goals, plans, knowledge, rumors and events persist in the DB.

### Exact economy
- Money is integer copper only.
- Every debit/credit is validated.
- Impossible payments fail atomically.
- Ledger stores exact post-transaction balances.

### Needs
Each NPC has continuously changing deprivation values:
- hunger;
- fatigue;
- loneliness;
- danger.

Need growth uses minute accumulators, so 15-minute simulation ticks do not lose fractional progression. Needs can override plans: a hungry or exhausted NPC does not keep working simply because a plot wants it.

### Goals + initiative
NPCs have persistent goals with priority/progress/deadlines/source. They can create new goals without player input, for example:
- a guard investigates a credible security rumor;
- a merchant reacts to low food stock;
- a publisher/craftsman sources materials when a project is blocked;
- an NPC with no active goal creates a role-appropriate objective.

Repeated goals have cooldowns so an NPC does not finish and instantly recreate the same task every few minutes.

### Plans
Goals materialize into explicit rule plans and plan steps. These exist independently of narrative prose and are inspectable in SQLite.

### Resource-backed projects
Publishing and instrument work consume actual resources.
- publishing consumes paper + ink and creates publications;
- instrument production consumes wood + string and creates instruments;
- shortages trigger sourcing behavior;
- sourcing costs money and changes resource stocks.

### Rumors and information boundaries
Objective truth is stored separately from beliefs. A rumor starts with one actor, spreads only through actual social contact, loses confidence, can distort estimates/severity, and never automatically becomes objective knowledge.

### Contextual reactions
The engine resolves reactions from measurable factors rather than generic prose:
- personal preferences;
- relationship to source;
- trust/respect/fear;
- hunger/fatigue;
- curiosity/discipline/conformity;
- novelty;
- disruption;
- local norms;
- crowd pressure;
- seeded randomness.

The result is structured (`attention`, `score`, `category`, `reasons`, `factors`). The future LLM layer should narrate that result without replacing it.

### Player boundary
The autonomous scheduler never moves or spends money for an actor marked `is_player=1`. Player needs may age with time, but meaningful player actions remain external input.

## Validation

`python -m unittest -v test_v02.py`

Current local result after the continuous-needs fix: **14/14 tests pass**.

Covered:
- atomic economy;
- player not autopiloted;
- needs accumulate correctly across small ticks;
- needs override plans;
- resource consumption;
- rumor propagation without global knowledge leak;
- NPC-generated goals;
- low-stock merchant initiative;
- plans generated from goals;
- SQLite persistence;
- 3-day autonomous world run;
- deterministic seeded replay;
- heterogeneous contextual reactions;
- reaction reasoning factors.

## Seven-day no-player probe

`python v02_probe.py --days 7`

The seeded lab reaches T+124 08:00 with Arlequino untouched while NPCs independently travel, sleep, eat, socialize, trade, train, publish, craft, investigate rumors, replenish project materials and create/complete goals.

On the current deterministic seed after the need-accumulator fix the local 7-day probe produced:
- 1,289 engine events;
- 60 NPC initiative events;
- rumor held by 6 actors through contact, not global broadcast;
- 12 actual rumor-share events;
- 7 project-material restocks;
- 20 publishing work events;
- 35 crafting work events;
- 32 rumor-investigation actions;
- 91 social interactions;
- 59 completed goals;
- 21 bought meals + 3 inventory meals;
- 85 sleep events and 147 rest events;
- 0 autonomous player actions.

These counts are diagnostic, not target gameplay pacing. v0.3 should compress routine simulation rather than maximize event volume.

## Persistence benchmark

`python v02_benchmark.py`

On the development container, 200 tiny SQLite checkpoint commits after the fix produced approximately:
- median: ~0.8 ms;
- p95: ~1.8 ms;
- observed max: ~11.3 ms.

This measures the local storage layer only, not an eventual app/network/UI pipeline. It demonstrates that multi-minute GitHub saving is not required for the game runtime.

## Known limitations before campaign migration

v0.2 is still a laboratory, not the target game engine. Important missing layers:
- population scaling / level of detail for hundreds or thousands of NPCs;
- factions/institutions as autonomous agents;
- weather, travel hazards and regional simulation;
- combat/skills/checks/injury/death;
- laws/crime/authority/reputation;
- market price formation and broader supply chains;
- robust calendar/schedules/appointments;
- memory salience and forgetting;
- relationship drives beyond scalar affinity/trust;
- event significance filtering for the LLM;
- canon-era world events and causal propagation;
- migration of the real Arlequino campaign.

## Gate for v0.3

Do not migrate the live campaign until v0.3 proves:
1. factions act without the player;
2. events propagate across locations with realistic delay;
3. routine NPC simulation can be compressed without simulating every minute for everyone;
4. economy has local prices/supply/demand without drift;
5. the LLM receives a small, relevance-filtered context instead of the whole database.
