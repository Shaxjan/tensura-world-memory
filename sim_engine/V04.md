# Tensura Simulation Engine v0.4 — Rules, Consequences & Player Firewall

v0.4 is the next laboratory layer. It sits on top of v0.3 instead of replacing it.

The goal is to stop the LLM from being able to mutate the world arbitrarily. The model may interpret a player's natural-language intent, but every meaningful state change must be accepted by deterministic engine rules.

The live Arlequino campaign is still **not migrated**.

## What v0.4 adds

### 1. Player command firewall

`submit_player_command()` accepts only a small allow-list of state-changing commands:

- `travel`
- `buy`
- `attempt`
- `attack`
- `crime`
- `attend`
- `wait`

Each command has an exact parameter schema.

Unknown commands such as `set_cash`, extra fields such as `cash_copper`, invalid destinations, impossible purchases and remote attacks are rejected and written to `action_log` without mutating the requested state.

This is the first hard boundary between what the player says, what the LLM thinks the player means, and what the simulation engine actually permits. The LLM is not allowed to execute arbitrary SQL/state patches.

### 2. Auditable skill checks

Checks are deterministic from the persistent world RNG. Every check stores actor, skill, DC, d20 roll, skill bonus, total, success/failure, namespace and world time. Natural 1 fails and natural 20 succeeds. The narrator receives the result after the roll; it does not invent the roll.

### 3. Combat, wounds and death

Attacks require real co-location and a living attacker/target. The engine resolves attack roll, defense from armor, deterministic damage, critical damage, HP reduction, injury creation and death at zero HP. Combat results are persisted and auditable. This is intentionally a small combat model; v0.4 tests the authority boundary, not final Tensura power scaling.

### 4. Law and reputation

Regions can define laws with severity, fine and possible jail duration. A crime can be witnessed or unwitnessed. Witnessing is derived from regional security + seeded randomness unless a test explicitly forces a state. A reported crime changes regional reputation and creates a delayed legal case. The authority issues a summons later through the world clock; it does not require the player to trigger the response. Unobserved crimes do not instantly create impossible police knowledge.

### 5. Appointments without player autopilot

Named actors can schedule persistent appointments with location, time and grace period. NPC–NPC appointments may resolve automatically when both participants are actually present.

Appointments involving the player are different: **the engine never marks the player as attending merely because the player happens to be in the same region.** At the due time the appointment becomes `waiting`. The player must explicitly submit `attend`. If the grace period expires, it becomes `missed`.

### 6. Salient memory and forgetting

Memories store summary, salience, emotional weight, decay rate and last recall time. High-salience or strongly emotional memories can persist indefinitely. Trivial memories decay and eventually become `forgotten`. This is an explicit world-memory model, not accidental LLM context truncation.

### 7. Canon/world event injection

A canon event is scheduled with objective occurrence time, origin region, significance, payload and information spread mode. When it occurs, it becomes objective world truth at the origin and uses v0.3's delayed regional information network. It does **not** automatically enter every NPC's or player's knowledge. An actor can learn it only when the fact is actually available locally or through some future explicit source.

### 8. v0.3 remains active underneath

v0.4 does not remove regional markets, production/consumption, caravans, autonomous factions, delayed information, population LOD or relevance-filtered context. The v0.4 clock advances the existing v0.3 world in chunks while also honoring actor travel, appointments, legal cases, canon events and memory decay.

## Local validation

Current development result: **17/17 v0.4 tests pass**.

Covered: arbitrary mutation command rejected; extra hidden state fields rejected; travel validated and delayed; invalid travel leaves state unchanged; market purchase atomic; seeded checks deterministic and auditable; remote combat rejected; combat can produce injury/death; witnessed crime creates delayed legal response; unwitnessed crime does not create magical police knowledge; player appointment never auto-attends; explicit attendance works; missed appointments survive long jumps; trivial memory decays; important memory persists; canon event does not leak directly to player knowledge; v0.3 macro simulation continues under v0.4.

## 60-day no-command probe

A local integration probe with no player commands produced: player cash unchanged; player region unchanged; player HP unchanged; player stayed idle; 240 regional macro ticks; canon event occurred; its information eventually reached the Blumund regional belief network; it still did not automatically appear in player knowledge; the unattended player appointment became `missed`, not magically `met`; important seeded memory remained active; trivial probe memory became forgotten; LLM context remained well below the 8k-character guardrail.

The exact faction/event counts depend on the full v0.3 base and are diagnostic, not gameplay targets.

## Migration gate

The live campaign should still not move yet.

Before migration, v0.5 should prove:

1. natural-language player intent can be mapped to the command firewall without silently inventing parameters;
2. Tensura-specific skill/power scaling can replace the tiny generic combat model;
3. healing, incapacitation and non-lethal outcomes exist;
4. crimes can involve witnesses with identities, testimony and evidence decay;
5. NPC relationship memory changes future decisions, not just narration;
6. named NPC routines and travel plans coexist with appointments;
7. the engine can produce a compact GM packet that includes only perceivable/relevant state;
8. a snapshot/import tool can map a real campaign into SQLite with an integrity report and no guessed UNKNOWNs.

Only after that should the current Arlequino history be imported.
