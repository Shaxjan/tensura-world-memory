# Simulation Engine v1.0.1 — Live Stability Hotfix

Triggered by the first real post-cutover play test.

Observed production failure:
- two consecutive local-movement turns took ~1m36s each;
- runtime remained at `journal_seq=0`, so neither accepted player intent became authoritative;
- the GM incorrectly treated the training yard as unknown even though `memory/places.json` already preserves three Eurazania training locations;
- v1.0 could store `local_navigation` pending state but could not autonomously finish a normal walk to a known local place.

## Fixes

1. Known local destinations resolve as finite engine actions.
2. Current v159 continuity disambiguates bare "training yard" to `большой тренировочный двор Борги` only because the saved current action is explicitly heading to Borga. This does not assert Borga is present there.
3. Unknown destinations still fail closed / remain pending.
4. Local travel advances the authoritative clock and therefore runs the same autonomy scheduler.
5. Default uncalibrated same-city travel is 12 minutes. This is prospective mechanical calibration, not retrospective geographic canon.
6. Repeating a command to the place already reached is a zero-minute no-op rather than another endless walk.
7. A repeated unresolved unknown navigation reuses the existing pending resolution rather than creating a duplicate.
8. Remote live play now uses an append-only request queue. GM creates one `runtime/requests/rNNNNNN.json`; GitHub Actions executes the engine, writes `runtime/journal/jNNNNNN.json`, and advances `runtime/runtime_state.json`.
9. Runtime pointer becomes engine `1.0.1`; the immutable v159 base checkpoint remains v1.0-compatible and unchanged.

## Performance intent

A same-chat GM should no longer reconstruct the entire historical repository per turn. Preferred path:
- read the tiny runtime pointer;
- create one request file for the next sequence;
- wait for the runtime bot commit;
- read the resulting journal event / new pointer;
- narrate from that result.

The GitHub-hosted queue is still not a millisecond game server. It is a reliability/latency hotfix until the runtime is moved to a persistent service.
