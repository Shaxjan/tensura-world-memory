# Simulation Engine v1.0.9 — Session Read-Model Repair

## Причина

После v1.0.8 authoritative `scene_pending_resolution` уже не содержал pending для старых подходов r11/r12, и текущий `scene.pending_resolutions` был пуст. Но сохранённый `last_turn` в `runtime/session_state.json` всё ещё содержал старый снимок pending ids 3/4.

Это не возвращало pending в authoritative мир, но делало fast-path read-model внутренне противоречивым.

## Правило v1.0.9

`last_turn.pending_resolutions` — не архивный список того, что когда-то было pending в момент хода. В текущем session read-model он должен содержать только те pending, которые **сейчас** имеют `scene_pending_resolution.status = 'pending'` для игрока.

Исторические cancelled/repaired/resolved rows остаются в БД и journal для аудита, но не показываются как текущие pending.

## Narration contract

Если stale pending отфильтрован:

- из `must_preserve` удаляется устаревшее `pending outcomes remain pending`;
- добавляется `historical repaired pending are not current pending`;
- verbatim player text, event key и сам последний игровой ход не меняются.

## Activation

v1.0.9 activation:

- zero-time;
- не меняет деньги, регион, локацию, Character Core, память или отношения;
- не создаёт player/NPC action;
- добавляет только append-only system runtime event и пересобирает session read-model по authoritative pending status.

## Invariant

Текущий `scene.pending_resolutions` и `last_turn.pending_resolutions` не обязаны быть исторически одинаковыми, но оба не могут утверждать `pending` для row, который authoritative runtime уже отменил/разрешил.
