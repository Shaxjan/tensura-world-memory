# Simulation Engine v1.0.13 Candidate — Grounded Character Agent Runtime

Status: **candidate only; not activated in LIVE.** Current authoritative pointer remains v1.0.12 until a separate activation gate is explicitly passed.

## Objective

Bring the already-tested Character Agent contract, grounded Rena profile, shadow replay boundary and deterministic Character Decision semantics into an isolated copy of the real v1.0.12 checkpoint/journal runtime.

This version is deliberately conservative. It proves migration and replay before enabling production gameplay routing.

## Compatibility rule

v1.0.13 candidate adds **no SQLite tables**.

All candidate Character Agent state is stored in the existing production `facts`, `actor_knowledge` and `events` tables. This is required because the v1.0 portable state hash includes all non-excluded tables. Adding a table would change the imported pre-activation hash and break proof that the candidate started from exactly the current LIVE state.

`load_repository_runtime_v113_candidate()` must therefore:

1. read the current v1.0.12 pointer;
2. import the current base checkpoint into a v1.0.13 candidate world;
3. replay the existing immutable v1.0.12 journal;
4. reproduce the current LIVE head hash exactly;
5. only then allow candidate events.

## Prospective Rena activation

`character_agent_v113_activation` materializes:

- a source-grounded Rena Character Core from preserved authoritative evidence;
- an empty Character Agent private continuity state.

Activation must not:

- advance world time;
- change player cash or region;
- invent Rena's current location;
- infer Rena's current mood;
- create relationship deltas;
- create episodic memories;
- create retroactive NPC decisions/responses;
- replace the last real gameplay turn.

## Candidate decision route

The only enabled route is `mode = candidate_rehearsal_fixture`.

This is intentional. Production gameplay is **not** allowed to submit a Character Agent context directly. The candidate verifies that the context contains the exact engine-owned Rena Character Core. A modified/invented core is rejected.

The next production-routing version must build observations, visibility and causal fact availability directly from authoritative engine state rather than trusting client payloads.

## Committed candidate effects

A validated Character Agent decision may create, inside the isolated candidate DB:

- private relationship delta since Character Agent activation;
- private episodic memories with deterministic ids;
- last private emotion for continuity;
- a committed structured decision fact;
- a public-only NPC response fact;
- direct player knowledge of that public response;
- a visible response event.

It may not gain authority over cash, inventory, spawning, teleportation or unrelated global world state through this route.

## Full-engine rehearsal

`v113_rehearsal.py` performs:

```text
current LIVE v1.0.12 seq N
  -> candidate import/replay; exact LIVE head hash required
  -> v1.0.13 activation event at N+1
  -> prove no retroactive response/memory/relationship mutation
  -> build engine-owned Rena context in explicit rehearsal-fixture mode
  -> shadow provider called once
  -> duplicate shadow turn replays without provider recall
  -> v1.0.13 Character Agent decision event at N+2
  -> commit bounded private continuity + public response
  -> rebuild session without replacing last real gameplay turn
  -> fresh candidate DB from current LIVE
  -> replay N+1 and N+2 through normal runtime journal machinery
  -> exact final state-hash equality required
```

The scripted Rena response used by rehearsal is fixture data only and is never canonical dialogue.

## Still required before LIVE activation

- engine-owned current-scene routing for Rena visibility and observations;
- causal knowledge extraction from authoritative `actor_knowledge`/facts rather than fixture inputs;
- provider timeout/error/fallback behavior;
- complex natural-language semantic claim verification;
- conversion of eligible real player turns into Character Agent opportunities;
- session projection of a real committed Rena response onto the associated player turn;
- coexistence/arbitration with the old Borga v1.0.10 response resolver;
- multi-character routing policy;
- activation script/pointer migration and rollback bundle;
- final freshness check against the latest LIVE head immediately before any activation.

Until those gates pass, v1.0.13 remains a candidate and LIVE stays v1.0.12.
