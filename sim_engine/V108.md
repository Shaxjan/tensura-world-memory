# Simulation Engine v1.0.8 — Visible Local Approach Repair

## Цель

Исправить реальный LIVE-дефект: generic v0.10 scene bridge превращал `Подхожу к Борге` в `local_navigation pending`, даже когда Борга уже был напрямую видим в той же living scene.

## Новое правило

Явный подход к именованному NPC разрешается движком как конечное same-scene действие только если одновременно:

1. текст действительно содержит язык приближения (`подхожу`, `подойти`, `приближаюсь` и близкие формы);
2. ровно один именованный target безопасно grounded через v1.0.6 token/inflection matcher;
3. этот target прямо сейчас присутствует в `named_observations` со статусом `visible`;
4. игрок остаётся в той же локальной living scene.

`Подхожу` без имени не привязывается к Борге автоматически. Если target не видим, v1.0.8 не изобретает его позицию и не объявляет подход успешным.

## Время

Same-scene approach занимает меньше минутной гранулярности текущего world clock и поэтому фиксируется как `approach_minutes = 0`. Это не межлокационное перемещение и не повод выдумывать расстояние или геометрию маршрута.

## NPC awareness

Физическое приближение само по себе НЕ утверждает:

- что NPC обратил внимание;
- реплику или реакцию NPC;
- эмоцию;
- согласие/одобрение;
- изменение отношений;
- reciprocal memory.

v1.0.7 Causal Encounter Memory продолжает работать для причинно наблюдаемого обращения/взаимодействия. v1.0.8 не создаёт память только из движения.

## LIVE repair

Activation append-only закрывает два уже известных ложных pending:

- `chat-20260824-approach-borga-r000011`;
- `chat-20260824-approach-r000012`.

Repair отменяет только их `local_navigation` pending и помечает старые scene actions как parser-repaired. Он НЕ объявляет задним числом, что движение состоялось.

Activation обязана сохранить:

- world time;
- player cash;
- player region/location;
- последний игровой ход;
- causal memory Борги от последующего приветствия;
- immutable старые journal events.

## Guardrails

- UNKNOWN остаётся UNKNOWN.
- Bare approach не получает скрытый target.
- Видимость требуется непосредственно перед выполнением.
- Нет автоматической NPC memory от движения.
- Нет NPC response/consent/relationship inference.
- Нет второго scheduler или автономного clock.
