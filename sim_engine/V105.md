# Simulation Engine v1.0.5 — Character Autonomy Execution

v1.0.5 makes the first persistent Character Core **act through the existing world scheduler**. It is intentionally narrower than a full AI personality system: Borga gets causal autonomous work execution, not invented psychology.

## Why this layer exists

v1.0.4 gave Borga a persistent identity and daily role plan, but his imported `task:borga` commitment still used the old generic `task_progress` handler. That meant the world could record an abstract work tick without checking whether Borga's own Character Plan currently grounded that work.

v1.0.5 removes that split-brain behavior.

## One scheduler, one character life

The engine does **not** create a second NPC clock or a duplicate Borga task.

The already-authoritative commitment remains:

- commitment key: `task:borga`;
- owner: Borga;
- kind: `npc_task`;
- assignment source: the preserved festival/tournament work already in runtime.

Activation changes only its runtime handler from generic `task_progress` to `character_task_v105`.

The existing `autonomy_runtime` row keeps its:

- `next_due_at`;
- cadence;
- tick count;
- active status.

Therefore character autonomy runs on the same clock and queue as every other autonomous commitment.

## Grounded workstreams

The first Character Autonomy state derives workstreams only from words already present in Borga's preserved assignment:

- combat rules;
- admissions;
- judges;
- testing;
- tournament operations.

The new schema is not permission to invent extra responsibilities.

## Decision at a scheduler tick

When `task:borga` becomes due, the engine checks Borga's current persistent Character Plan.

### Grounded role-duty block

If the current block is `role_duty` with an exact grounded training site, the engine deterministically selects one preserved workstream and records a unit of effort.

This means **work happened**, but it does not mean the task or workstream is complete.

### Travel / personal / unresolved block

If the current block is `local_travel`, `unresolved_personal_time` or `unresolved_region_activity`, the engine records `character_work_deferred`.

It does not teleport Borga to a workplace and does not invent an exact position.

## Completion rule

v1.0.5 never auto-completes Borga's assignment merely because enough scheduler ticks have occurred.

Completion needs a later explicit grounded condition or a future mechanic capable of evaluating actual deliverables. Effort counters are evidence of ongoing work, not a hidden progress bar that magically finishes canon.

## Visibility and knowledge

Character Autonomy decisions are hidden engine state.

They are not automatically known by:

- Arlequino;
- the narrator;
- ambient NPCs;
- other named characters.

The player can learn about Borga's work only through a causal channel such as direct observation, testimony, report or another explicit transmission.

## Activation

The v1.0.4 head is compacted unchanged into a new v1.0.5 base checkpoint. Activation is a new append-only `character_autonomy_activation` event.

Activation:

- consumes zero game minutes;
- changes no player choice;
- changes no player cash or region;
- preserves the last gameplay turn;
- preserves Borga scheduler timing and accumulated ticks;
- only wires the specialized handler and persistent autonomy state.

## Still deliberately out of scope

v1.0.5 does not yet add:

- authored personality;
- free-form goal generation;
- relationship dynamics;
- episodic memory formation;
- biological needs;
- private economy/possessions;
- LLM agent calls;
- automatic task completion;
- omniscient narration of hidden work.

The design principle remains: make one character causally autonomous before making many characters superficially clever.
