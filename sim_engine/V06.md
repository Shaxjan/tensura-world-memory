# Tensura Simulation Engine v0.6 — Migration Rehearsal & Durable GM Loop

v0.6 deliberately adds **less world breadth**. It focuses on the transition from a GitHub-chat prototype to a real local simulation runtime without losing campaign history or giving the LLM authority over state.

## 1. Real repository migration rehearsal

`v06_rehearsal.py` reads the repository itself:

- `live_state.json` pointer;
- its exact pointed `live_vNNN/delta.json`;
- every available `live_v*/delta.json` source document;
- `world_save.json` archive when present.

It verifies pointer/version consistency, parses current world time and money deterministically, and maps the current region only when the textual location contains exactly one explicit known region alias.

Every source file is copied verbatim into the disposable SQLite database with SHA-256 and byte count. Valid JSON is parsed for semantic migration; malformed historical deltas are still archived byte-for-byte and reported as blockers. A malformed **current pointed delta** remains a hard failure. UNKNOWN values are preserved rather than filled. This means semantic migration can remain incomplete without losing source history.

The rehearsal distinguishes:

- `rehearsal_ready`: exact current core can be preserved and represented safely;
- `live_cutover_ready`: every gameplay subsystem is sufficiently normalized for the real campaign to switch runtimes.

v0.6 intentionally keeps live cutover false while power/skills, named-NPC exact positions, numeric relationship state and all separate project funds are not authoritatively mapped.

## 2. No fake combat or world baseline during migration

The migration seed uses compatible v0.3 region identifiers plus the v0.4/v0.5 schemas, but does **not** import laboratory v0.4/v0.5 character stats, power values or relationship numbers.

All gameplay commands are capability-locked in the migration rehearsal. Exact player time/cash/region are not enough to enable play: the v0.3 regional scaffold does not constitute authoritative live market prices, route durations or autonomous-world state. Synthetic markets, routes, factions, population pressure and events are purged from the migration database and are never exposed in its GM packet. Commands are enabled only after their real campaign baselines are imported.

## 3. Idempotent GM turn loop

`process_player_turn(turn_key, raw_text)` implements:

`player text -> deterministic grounded proposal -> capability gate -> engine command -> compact GM packet -> local checkpoint -> narration contract`

A unique `turn_key` makes execution idempotent. Replaying the same turn after a reconnect/restart returns the stored result instead of charging money, advancing time or applying an action twice.

An optional external/LLM intent is accepted only when command and every parameter exactly match the deterministic grounded proposal.

## 4. Narration is downstream of state

The narration contract explicitly separates prose from authority. The narrator receives the engine result and perceivable packet. It may describe them, but it may not mutate state, leak hidden facts, invent UNKNOWNs, or choose the player's dialogue/feelings/decisions.

`record_narration()` verifies that authoritative state still matches the turn checkpoint before accepting prose. If some external writer changed the state after the GM packet was generated, narration is rejected with `state_changed_after_packet` and the turn must be rebuilt.

## 5. SQLite checkpoint

An accepted turn writes a compact canonical state snapshot and SHA-256 into `checkpoints`. SQLite itself is the durable save; this row is an audit/recovery marker, not a remote SAVE rewrite.

`verify_latest_checkpoint()` detects out-of-band mutations.

## Validation

```bash
cd sim_engine
python -m unittest -v test_v06.py
python v06_probe.py --turns 100
python v06_rehearsal.py --repo-root .. --out /tmp/v06_rehearsal.json
```

The CI rehearsal runs against the **actual repository state at that commit**, not a hand-copied campaign fixture.

## Gate after v0.6

Do not switch the live Arlequino campaign merely because the rehearsal can archive it.

The next decision is driven by the generated blocker report. Resolve only the blockers required for live play, then perform a second rehearsal and compare critical fields against GitHub source history. Live cutover happens only when `live_cutover_ready=true` and an end-to-end turn can resume from the SQLite checkpoint without GitHub state reads.

## First real-repository finding

The first v0.6 rehearsal against the actual repository found four malformed historical delta files: **v114, v148, v150 and v152**. The current pointed delta remained valid. v0.6 therefore treats these four files as preserved raw historical sources and adds an explicit semantic-cutover blocker instead of discarding them or pretending they are valid JSON.
