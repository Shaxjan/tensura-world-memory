# Tensura Simulation Engine v0.5 — Grounded Intent & Living Consequences

v0.5 remains a laboratory layer. The live Arlequino campaign is **not migrated**.

## Purpose

v0.4 proved that deterministic rules can own state changes. v0.5 attacks the next failure mode: an LLM can still misread free text, invent a destination/target/difficulty, flatten Tensura power differences, or narrate social/legal consequences that the world has not earned.

## Added in v0.5

### Grounded natural-language intent
`propose_text_intent()` performs deliberately conservative rule parsing. It extracts only explicit known regions, actors, commodities, quantities and action keywords. If a required value is missing or ambiguous, status is `needs_clarification`; nothing executes.

`validate_external_intent()` is the guard for an eventual LLM parser: an external proposal is rejected unless its command and every parameter agree with the deterministic grounded proposal. This makes “the model silently decided I meant Dwargon” invalid by construction.

Supported lab intents: travel, buy, strike, social approach, treatment and wait. Strike mode is never guessed: lethal/non-lethal intent must be explicit or the proposal asks for clarification. The legacy v0.4 `attack` command is disabled in v0.5. The parser is intentionally narrow; unsupported text is safer than invented state.

### Tensura-facing power layer
Actors receive a threat rank, magicule budget and physical/magic/control/durability/regeneration values. This is an engine-facing balancing model, **not a claim that the current numeric seed is final canon power scaling**.

Combat now considers rank gap and durability. A sufficiently outclassed attack can be ineffective. Non-lethal attacks cannot kill. Reaching zero HP normally produces incapacitation before death unless the damage is overwhelming or the target is already incapacitated.

### Healing and conditions
Conditions are persistent records (`wounded`, `incapacitated`, `unconscious`, etc.). First aid and healing magic are auditable checks. Successful treatment restores HP and can resolve appropriate conditions. Regeneration is processed by the world clock.

### Named witnesses, testimony and evidence
Crimes no longer need a magical boolean witness in normal operation. The engine enumerates real co-located named NPCs, resolves perception, stores witness identity/confidence/willingness, creates testimony only when a witness is willing, and stores physical evidence separately. Evidence decays with world time. A legal case requires sufficient actual testimony/evidence.

### Relationship memory affects decisions
Social bonds track affinity, trust, respect, fear and obligation. Relationship events create explicit memories. `decision_score()` uses those values and salient relationship memories, so betrayal/helping can change later NPC willingness rather than existing only in prose.

### Named NPC plans and appointment conflicts
Named NPCs can have recurring routines and explicit travel plans. Routines can change activity or start travel only when time/location permit. Before planned departure the scheduler checks real travel time and upcoming appointments. A conflicting appointment can defer the trip. The same scheduler explicitly invalidates any autonomous plan assigned to the player.

### Compact GM packet
`build_gm_packet()` exposes only player state, local/perceivable actors, local market/events, player-known facts/memories, conditions/legal/appointments and the command contract. Remote world truth is not dumped into the narrator context. A hard 8k-character guardrail remains.

### Campaign import audit
`audit_campaign_snapshot()` and `apply_campaign_snapshot()` are strict. Required `UNKNOWN` fields block import. Unmapped regions block import. Exact money strings such as `21g 66s 41c` are parsed deterministically. The importer records an integrity report and does not manufacture missing values.

## Acceptance tests

`python -m unittest -v test_v05.py`

Current local result: **24/24 tests pass**. The suite covers grounded intent, clarification instead of guessing, hostile external-intent invention rejection, explicit lethal/non-lethal intent, disabling the legacy generic attack command, engine-derived social DC, non-lethal combat, incapacitation, treatment, rank mismatch, named witnesses, no testimony or instant legal case for an unobserved crime, evidence decay, relationship memory affecting decisions, NPC routines, plan/appointment conflicts, player-autonomy guard, compact hidden-safe GM packet, strict import UNKNOWN handling and a 30-day no-player-autopilot run.

`python v05_probe.py --days 30` currently produces: 120 macro ticks, 360 autonomous faction actions, a 977-character GM packet, one deferred named-NPC plan due to an appointment conflict, expired physical evidence after 30 days, and **no autonomous change** to player region, cash or HP. These are diagnostic lab numbers, not target pacing.

## Gate for v0.6

Before live campaign migration, v0.6 should focus on two things rather than adding breadth:

1. **real campaign migration rehearsal** into a disposable database with a field-by-field integrity report against GitHub history;
2. **GM loop integration**: free-text player input -> grounded proposal -> engine transaction -> compact GM packet -> narration -> automatic local SQLite checkpoint.

The rehearsal must prove that no current campaign fact is guessed, dropped or silently normalized. Only then should the live campaign be moved off the GitHub-save runtime.
