# SONG ARCHIVE WRITE RULE

1. Одна песня = один файл = один GitHub write.
2. Сохранять весь пользовательский текст песни целиком и дословно в одном UTF-8 файле, например `song_archive/tmy_knyaz.txt`.
3. Не разбивать песню по строкам, куплетам или частям.
4. Не создавать отдельный commit на каждую строку.
5. Если песня уже существует — один раз обновить этот файл целиком.
6. Метаданные либо хранить в том же файле, либо максимум в одном отдельном JSON, только если они действительно нужны.
7. Канонический источник текста песни — единый UTF-8 файл песни. Старые построчные/фрагментированные архивы не использовать как рабочий формат для новых сохранений.
8. `song_archive/` предназначен только для ПРОВЕРЕННЫХ ПОЛНЫХ текстов. Название коммита, summary сцены, известный припев или несколько строк не являются доказательством полного текста.
9. Если полного дословного текста нет, запрещено реконструировать недостающие строки по памяти, интернету, оригиналу песни или смыслу. Сохранять найденные фрагменты в `song_fragments/`, а в `memory/songs.json` ставить статус `PARTIAL_EXACT` или `TEXT_LOST`.
10. После получения полного текста от пользователя или полного восстановления из его сохранённых данных: создать/обновить один файл в `song_archive/`, проверить начало/конец и только затем поставить статус `FULL_CANONICAL`.
11. Для пользовательской адаптации хранить именно адаптированный текст, без исправлений орфографии, ритма, имён, терминов и опечаток, если пользователь сам их не исправил.
12. Старые shard-папки и исторические commits могут сохраняться для аудита, но не имеют приоритета над единым проверенным файлом в `song_archive/`.
